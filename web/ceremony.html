The key ceremony

A key nobody chose, made inside the chip.

How a fresh ATECC608 becomes a diykey key. Its rules are written and locked. Then the chip makes a key that can't be read out, and the key is sealed. Two parts and ten steps, three of them permanent, all on the Cardputer's own screen and keys.

A plan. No firmware runs it yet. The screens on this page are mockups, drawn by the signer's own drawing code and fonts the way the Cardputer would draw them (core/examples/ceremony.rs). The steps themselves ran on silicon, from the MicroPython signer this one was ported from, on two ATECC608A chips (what ran).

  1. FactoryNothing locked. Its rules are Microchip's.
  2. P3Rules lockedThe table, checked by CRC.
  3. P5Data lockedZeros, the record. Slot 0 empty.
  4. K1Key madeBy the chip's GenKey.
  5. K3SealedThe key can't change again.

1Prepare the chip

Write the rules, lock them, fill the unused slots with zeros, and lock the data zone. After that, the chip's own rules let nothing write a key into slot 0. Only the chip's GenKey can make one there.

2Make your key

GenKey makes the key inside the chip. Test it, seal it, and work out its Safe signer address. The key never leaves the chip, and there is nothing to write down.

Part 1 makes no key, so it can be done by someone else, and Part 2 still gives a key only you asked for. That makes a branded key possible later. To start with, you run both parts on your own Cardputer.

What you trust, and what you don't

Trusted

The chip

Microchip's silicon makes the key with its own random number generator, and keeps it. An ATECC608 can't prove it is genuine, so buy it from a known seller.

Trusted

The ceremony image you flash

It is the one program that could cheat: before the data lock it could write a key it knows and say GenKey made it. Build it yourself, or compare its SHA-256 with the page's.

Not trusted

The computer

Nothing secret goes over the cable. What goes over USB is the rules, the public key and test signatures.

Not trusted

Whoever ran Part 1

After the data lock the chip refuses to write a key into slot 0, and K1 always makes a new one, whatever was there.

The ceremony doesn't add secure boot. Anyone with the cable could still flash a signer that shows one thing and signs another.

Part 1

Prepare the chip

Two permanent steps. After them, nothing can write a key into slot 0.

P1No changes

Read the chip

Reads everything. The page saves the factory config to the log.

Checks
It answers at 0x60. Revision 00006002, a 608A. Both zones open (55 55), slot locks FF FF. Random gives the fixed pattern of an unlocked chip. SelfTest passes.
Refuses
A used chip, a TrustFLEX or Trust&GO part (they come locked), an unknown revision. It says why.
Then
Write the chip's serial, as the screen groups it, on a sticker on its board.

P2Can be written again

Write the rules

Writes the table into the config zone, except the chip's own bytes (0–15 and 84–87), and reads it back.

Checks
The readback is the table. The screen shows the config CRC, and the page works it out on its own from P1's saved bytes. The two should match.

P3Permanent

Lock the rules

Lock, mode 0x00, with that CRC. The chip works out the CRC of what it holds and refuses if one byte differs. A refused lock locks nothing.

After
Config locked, the table unchanged, Random live.

P4Can be written again until P5

Zeros and the record

Zeros into slots 1–15, in 32-byte writes: before the data lock, the chip refuses 4-byte writes into secret slots. The record into OTP. The screen shows the data CRC.

Checks
Each write is accepted. P5's CRC checks what they wrote.

P5Permanent

Lock the data

Lock, mode 0x01, with the CRC of every slot that isn't a key (1–15, in order), then the OTP zone. Again, a single byte off and the chip locks nothing.

After
Data locked. OTP and slot 8 read in the clear; slot 1 can't be read. Slot 0's rules now hold: no Write, no PrivWrite, only GenKey.

P6No changes

Check

Reads it all back: both zones locked, the table, the record, counter 0. Slot 0 is checked empty with Info, which doesn't count as a use, so a prepared chip leaves Part 1 with counter 0 at 0.

The keys, and the gate in front of anything permanent

Enter

Does the step, or goes on.

Del

Backs out at any point, with one press. Nothing is written.

A red page

Type the last group of four in the chip's serial, from its sticker, then hold Enter for 3 seconds while a bar fills. Letting go early does nothing.

Part 2

Make your key

One permanent step. Unplug before the seal, and you start again with a new key.

K1Can be made again until K3

Make your key

GenKey, mode 0x04, on slot 0. Always, whatever is there: a key you didn't see made is replaced, never used. Reads the public key and shows its fingerprint.

Checks
Slot 0 holds a valid key and its public key reads back. GenKey on slot 1 is refused.

K2No changes

Test it

Signs two test transactions, each the WebAuthn message over a Safe hash the device works out itself from fixed fields: Base Sepolia, and a Safe address nobody controls, so the signatures can't approve anything. Never a digest from the computer.

Checks
The page checks both with WebCrypto, as it checks a passkey's. Counter 0 went up by exactly the signatures and key reads. Sign on slot 1 is refused.

K3Permanent

Seal your key

Lock, mode 0x82: slot 0 alone. From then on the chip refuses GenKey, Write and PrivWrite on that slot. Sign and reading the public key still work.

After
The slot locks read FE FF. The public key is the one K2 tested, and one more signature checks.

K4No changes

Its address

Works out the Safe signer address from the public key, with its blockie: the address Safe's passkey factory gives this key, the same on every chain. The Cardputer's and the page's should match.

The key and address in these pictures are a test vector's (vectors/webauthn.json), not a chip's. The serial and CRCs are a made-up chip's, worked out from the table.

Afterwards

  1. Flash the signer back. Its idle screen shows the chip; the page shows the key and its address.
  2. Check the address with the passkey factory's getSigner on Base Sepolia, from a block explorer or cast call. This page doesn't: it loads nothing from anywhere else.
  3. Add it as an owner of a testnet Safe, with a threshold you can reach without it, such as 2 of 3 with a passkey and a wallet.
  4. Don't send funds to the address. It only signs.

What to keep

The page saves every line the ceremony prints:

  • the serial, the revision and the factory config
  • the config CRC and the data CRC
  • the public key and the Safe signer address
  • counter 0 after each step
  • the ceremony image's commit and SHA-256

Nothing in it is secret. There is no seed phrase and no backup: lose the chip, and the Safe's other owners swap it out.

I2C address 0x60. CountMatch off. A 1.3 s watchdog. Both counters at 0. SecureBoot, KDF, IO protection, UseLock and VolatileKey off. The slot locks start at FF FF: a cleared bit at the config lock would seal slot 0 before it ever had a key.

The record, in OTP

64 bytes, written at P4 and frozen by P5: DK, the layout and table versions, the serial, the revision, the config CRC, the ceremony image's commit, who prepared it (its owner, or a diykey bench), and for a branded chip its number and the brand key's id.

It holds no key, because there is no key yet when it's frozen. The signer always reads the live key.

Decisions behind it

  • No PIN. The chip has no lockout: a 6-digit PIN falls in about 7 hours. The Safe's threshold is the protection.
  • A use counter. Every signature raises counter 0, which only goes up. After the data lock a public-key read counts too.
  • Its own firmware image. The write, lock and key commands live in a ceremony image. The signer keeps read commands, plus Sign.
  • The chip says where you are. Each step comes from the chip's state, so a restart resumes.

An option

A branded key

The project runs Part 1 on a bench. You run Part 2.

Part 1 is where the mistakes happen: a table, two CRCs, two permanent locks and the silicon's quirks. Part 2 is where the key is made. Because Part 1 makes no key, the project could prepare chips on a bench, add a brand, and send them out. Each owner then makes their own key.

  • The bench adds a brand at P4. The record says "a diykey bench" and the chip's number, and slot 8 holds the brand key's signature over the record.
  • Your Cardputer checks it before K1: the signature, under the brand key pinned in the firmware; the serial, revision and config CRC against the chip in front of it; both zones locked, slot 0 not sealed. The check runs on the Cardputer or the page, never on the chip being checked: a fake chip would just say yes.
  • The brand key is diykey key 0000: a Cardputer and a chip through the whole ceremony, its log published. It signs a brand the way the signer signs a transaction: from fields it shows, a digest it works out itself, Sign held. It is never a Safe owner.
diykey key 0042 0123 4a7b 9c2d 5e6f ee No key inside yet. Your Cardputer makes it.
What a brand proves

That the project's key signed this serial's record, for this table, and that the chip in front of you has that serial and that table, locked.

What it doesn't

That the silicon is the chip the bench branded. An ATECC608 has no factory certificate, so a fake could copy a real chip's serial, OTP and slot 8. A public list with one claim per serial limits that. Nothing more does.

For the launch, no brand. People who build one buy their own breakout, and the one to trust for Part 1 is themselves. A brand is worth its cost (key 0000's ceremony, a bench image, the check, labels, a public list) when the project hands out chips. Every chip gets slot 8 readable from the start, so a branded chip and your own run the same table.

What has run on silicon

From the MicroPython signer, on a Raspberry Pi Pico 2 W, with Adafruit 4314 breakouts (ATECC608A, revision 00006002). Its code isn't in this repository.

  1. 2026-09-26
    A fresh chip, the whole ceremony in the older order: the key made and sealed before the data lock, slot 8 secret. It settled the CRC's byte order in Lock, the data CRC's layout, that the chip refuses 4-byte writes into secret slots before the data lock and takes 32-byte ones, and that once the data zone is locked, a public-key read counts as a use.
  2. 2026-10-07
    A spare, with this table and in this order: the data lock, then the key, then the seal. GenKey works after the data lock on a slot that never held a key, and slot 8 reads in the clear and is in the data CRC. Refused afterwards, with counter 0 unmoved: GenKey on the sealed slot and on slot 1, Write to slots 0, 1 and 8, to OTP and the config, both zone locks again, Sign and Read on slot 1. A signature from it passed Safe's isValidSignatureForSigner on Base Sepolia; a wrong hash didn't.

Not run yet: a 608B

Adafruit doesn't say which part the 4314 carries now. P1 refuses revision 00006003 until a spare 608B has been through.

Not run yet: the Cardputer

Everything above ran from MicroPython on a Pico. The Rust driver's waits and the chip's power through the AMS1117 are new. A spare settles both.

Left untested: PrivWrite

After the data lock it should be refused. Testing it needs the command, and the signer won't have one.

Before you buy

A Cardputer v1.1, two ATECC608 breakouts (one is the spare), an AMS1117-3.3 module and a Grove cable: the shopping list.

Not the Cardputer-Adv. The v1.1 is being discontinued, and its successor reads its keyboard over I2C on G8, G9 and G11, the pins this firmware drives as outputs. Don't flash the signer on an Adv. And buy a blank chip: TrustFLEX and Trust&GO parts come locked.
